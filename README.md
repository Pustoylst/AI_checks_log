# Directum Log Analyzer — локальная Qwen3 8B

FastAPI-сервис для анализа JSON-логов Directum, больших JSONL-логов из сетевой папки и ошибок CI. Модель `qwen3:8b` работает через Ollama на этом компьютере, облачного резервного провайдера нет. Инструменты `read_git_file` и `search_code_in_repo` читают исходники внутри указанного корня репозитория. Предложение исправления само ничего не записывает: требуется подтверждение и проверяется точная замена. При применении меняется только выбранный файл: backup и дополнительные копии не создаются. Для отката используйте Git.

## Установка на Windows

Нужен Python 3.11 или новее. Команды выполняются из папки `AI_checks_log`:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установите Ollama для Windows: https://ollama.com/download/windows . Запустите приложение и откройте новый терминал:

```bat
ollama pull qwen3:8b
ollama list
.venv\Scripts\python.exe -m tools.check_config
```

Для скачивания модели (около 5,2 ГБ) нужен интернет. После скачивания локальный анализ и интерфейс не требуют интернета. GitHub-интеграция отдельно требует сеть и токен. Если Ollama уже установлен, но не работает, запустите приложение Ollama; `ollama serve` нужен только если сервер ещё не запущен.

## Настройки

По умолчанию всё готово для локальной модели. При необходимости скопируйте `.env.example` в `.env` и измените:

```env
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
OLLAMA_TIMEOUT_SECONDS=180
OLLAMA_NUM_CTX=8192
DIRECTUM_DOCS_PATH=../rx262
LOG_PREPROCESS_BUDGET_CHARS=14000
LOG_PREPROCESS_MAX_BYTES=536870912
LOG_OVERVIEW_BUDGET_CHARS=16000
LOG_OVERVIEW_MAX_FILES=1000
LOG_OVERVIEW_MAX_BYTES=3221225472
```

Разрешён только локальный HTTP-адрес модели; системный HTTP-прокси не используется. Ключ GigaChat больше не нужен, старые `GIGACHAT_*` игнорируются. Не включайте внешнюю трассировку LangSmith для конфиденциальных логов.

Большие логи из сетевой папки не отправляются в модель целиком: сервис делает компактную выжимку (по умолчанию до `LOG_PREPROCESS_BUDGET_CHARS=14000` символов). Для общей сводки по многим логам используется отдельный бюджет `LOG_OVERVIEW_BUDGET_CHARS=16000`. Для одной выжимки обычно достаточно `OLLAMA_NUM_CTX=8192`; для общей сводки с запасом под ответ лучше `16384` — это увеличит потребление памяти. Рассуждения модели отключены (`reasoning=False`) для уменьшения задержки. Это не гарантия качества: проверьте выводы по исходникам.

## Поиск по документации Directum RX (RAG)

При наличии соседней папки `rx262` сервис автоматически ищет по HTML-справке Directum RX 26.2 перед каждым анализом лога. Путь для поиска строится по сообщениям, исключениям, сервисам и сводке лога. Путь к документации по умолчанию определяется относительно расположения проекта; при необходимости задайте `DIRECTUM_DOCS_PATH`. Найденные фрагменты передаются модели до генерации ответа. Ответ дополняется точными путями найденных страниц; ссылки на несуществующие страницы или `https://rx262/` заменяются проверенным локальным источником. Если лог явно связан с Directum, но подходящих фрагментов нет, ответ сообщает об этом.

Поиск гибридный: SQLite FTS5/BM25 находит точные технические имена, BGE-M3 через локальную Ollama — близкие по смыслу фрагменты. Результаты объединяются методом Reciprocal Rank Fusion; до пяти выдержек передаются Qwen3. Векторы хранятся в SQLite в `%LOCALAPPDATA%\AI_checks_log\rag`, исходная справка не изменяется, внешних сервисов нет. Для вычислений используется NumPy.

После скачивания `bge-m3` постройте индекс из папки `AI_checks_log`:

```bat
.venv\Scripts\python.exe -m tools.index_documentation
```

Команда сохраняет каждую обработанную порцию: после прерывания её можно повторить. После изменения справки выполните её снова — уже рассчитанные фрагменты не пересчитываются. При смене версии модели строятся новые совместимые векторы. Анализ не запускает полную векторизацию сам: если индекс не готов или Ollama недоступна, используется BM25, а в ответе появляется предупреждение.

Настройки: `RAG_VECTOR_ENABLED=true`, `RAG_EMBEDDING_MODEL=bge-m3:latest`, `RAG_EMBEDDING_BATCH_SIZE=16`, `RAG_VECTOR_MIN_SIMILARITY=0.45` (порог косинусного сходства; требует оценки на реальных логах). Для отключения векторов задайте `RAG_VECTOR_ENABLED=false`. Проверка после индексации: `python -m tools.index_documentation --query "RabbitMQ connection refused"`.

## Запуск

```bat
.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/ . Выберите JSON-лог или текстовый файл .log/.txt (в том числе из `\\192.168.240.2\Logs`), при необходимости укажите корень репозитория, нажмите «Проверить лог». Затем «Предложить исправление», проверьте буквальный текст «Было / Станет» и только после проверки нажмите «Применить изменение». Форматирование результата — безопасный текст, без внешних скриптов и шрифтов. Модель не имеет инструмента записи файлов.

CLI:

```bat
.venv\Scripts\python.exe -m tools.analyze_json sample_log.json --repo .
```

При загруженной модели команда `ollama ps` показывает CPU/GPU-размещение. Измерьте скорость и качество на типичных обезличенных логах: причины, доказательства, реальные ссылки на прочитанный код, точный JSON исправления. Без установленной Ollama эти свойства нельзя подтвердить.

## Логи Directum из сетевой папки

По умолчанию сервис читает логи из `\\192.168.240.2\Logs` (`LOG_SHARE_PATH`). Доступ выполняется под учётной записью Windows, от имени которой запущен uvicorn; отдельные логин и пароль не хранятся. В интерфейсе есть третья вкладка «Логи Directum». Кнопка «Проанализировать все логи» сначала собирает общую сводку по всем (или последним 100/300) логам, затем автоматически отправляет её модели. Кнопка «Только сводка без модели» показывает ту же сводку без вызова Ollama. Сервис потоково читает файлы, объединяет повторяющиеся ошибки и предупреждения, показывает затронутые сервисы, периоды и файлы с наибольшим числом проблем. Для детального разбора выберите отдельный файл в списке или нажмите «Детальный анализ» у файла из сводки; при необходимости укажите вопрос, например «почему повторяется BrokerNotAvailableException». Файлы читаются напрямую и не копируются в репозиторий. Предложение исправления для этого источника пока не подключено — доступны список, скачивание, выжимка, общая сводка и анализ.

Проверка доступа без запуска модели:

```bat
.venv\Scripts\python.exe -m tools.list_share_logs
.venv\Scripts\python.exe -m tools.preprocess_log --share-file "AVP-EDU261-WS20.WebServer.2026-10-29.log" --focus errors
.venv\Scripts\python.exe -m tools.overview_logs --limit 0 --focus errors
```

Фактический размер папки на момент проверки: **646 файлов, 2,61 ГиБ**, медиана 1,57 МБ, p90 11,75 МБ, p99 22,6 МБ. Самые большие дневные файлы: `IntegrationService` — 205,6 МБ и `WebServer` — 136,2 МБ. Это JSON Lines в UTF-8: одна строка — один JSON-объект с полями `t`, `pid`, `tr`, `l`, `lg`, `mt`, `ex{type,m,stack}`, `args`, `cust`, `un`, `tn`, `v`. Большая часть объёма — уровни Trace/Info; ошибок обычно единицы или сотни на сотни тысяч строк.

Для `.log/.txt` (и `.json` больше 1 МиБ) сервис автоматически делает выжимку: считает строки и уровни, группирует ошибки/предупреждения по сигнатурам, убирает повторы, оставляет пример записи, сокращённый стек и несколько строк контекста до/после. Для ошибок с trace ID отдельно собираются связанные записи с тем же ID по всему JSONL-файлу, а не только соседние строки; цепочка ограничена и явно помечается, если часть событий опущена. Небольшие текстовые JSONL-загрузки также передаются модели с автоматически извлечёнными цепочками trace. Обработка больших файлов потоковая: файл не загружается целиком, поэтому память почти не зависит от его размера. Отчёт ограничен `LOG_PREPROCESS_BUDGET_CHARS`; исходный файл не изменяется. Максимальный размер обрабатываемого файла — `LOG_PREPROCESS_MAX_BYTES` (по умолчанию 512 МиБ). Маленькие `.json` с одним объектом по-прежнему разбираются напрямую. При анализе из сетевой папки маленький UTF-8 `.json` с несколькими JSON-объектами по одному на строку тоже проходит через выжимку; повреждённый JSON по-прежнему отклоняется. Скачивание больших файлов идёт потоком, без лимита 1 МиБ.

Общая сводка сканирует файлы от новых к старым. Охват ограничен `LOG_OVERVIEW_MAX_FILES` (по умолчанию 1000) и `LOG_OVERVIEW_MAX_BYTES` (по умолчанию 3 ГиБ); итоговый отчёт — `LOG_OVERVIEW_BUDGET_CHARS` (16 000 символов). Ошибки объединяются по типу исключения и нормализованному сообщению, поэтому одинаковые сбои из разных файлов и сервисов считаются вместе. Это синхронный запрос: на текущей папке 2,61 ГиБ он может занять несколько минут, интерфейс показывает прошедшее время. Сканирование списка ограничено `LOG_SHARE_SCAN_LIMIT`, в обычный список попадает не больше `LOG_SHARE_MAX_FILES`; для общей сводки используется отдельный лимит.

## API

- `GET /health` — только доступность FastAPI, не готовность модели. Для модели используйте `python -m tools.check_config`.
- `POST /analyze` — multipart `file`: непустой JSON-объект (.json) или текстовый .log/.txt, необязательный query `repo`. Текст поддерживает UTF-8 (с BOM или без), UTF-16 с BOM и Windows-1251. Стек вызовов и переводы строк сохраняются. Лимит загрузки — 1 МиБ, текстового лога — 12 000 символов: при превышении выберите фрагмент вокруг ошибки, файл не обрезается автоматически. Те же форматы доступны для предложения исправления. Исходный файл не изменяется; автоматического наблюдения за сетевой папкой нет.
- `GET /logs/share/files?limit=200` — список последних `.json/.log/.txt` из сетевой папки `LOG_SHARE_PATH`.
- `GET /logs/share/file?name=...` — скачать один лог из сетевой папки потоком, без копирования в репозиторий и без лимита 1 МиБ.
- `GET /logs/share/preprocess?name=...&focus=errors|all` — вернуть выжимку и статистику без вызова модели. `errors` — ошибки/предупреждения, `all` — ещё топ сообщений всех уровней.
- `POST /logs/share/overview?focus=errors|all&limit=0|100|300` — просканировать много логов и вернуть общую сводку и структурированные `stats` без вызова модели. `limit=0` или отсутствие параметра — все файлы до `LOG_OVERVIEW_MAX_FILES`.
- `POST /logs/share/overview/analyze?repo=...` — отправить ранее полученную сводку в модель; JSON-тело `report`, `stats`, необязательный `question`.
- `POST /logs/share/analyze?name=...&repo=...&focus=errors|all&question=...` — прочитать лог из сетевой папки, при необходимости предобработать и отправить на анализ; `repo` и `question` необязательны. В ответе есть `preprocessed` и `stats`.
- `POST /propose-fix?repo=...` — multipart `file`, предложение без записи файлов.
- `POST /apply-fix?repo=...` — JSON `path`, `explanation`, `old_text`, `new_text`, `approved`. Без `approved: true` — 403. Проверка пути и единственности исходного фрагмента, запись без резервных копий. Ответ содержит `path` и `message`.
- `GET /repository/status?repo=...` — локальный Git, без токена.
- `GET /ci/checks?ref=...`, `POST /ci/scan?repo=...`, `POST /ci/propose-fix?run_id=...&repo=...` — необязательный GitHub CI.
- `POST /github/pull-request?repo=...` — только после подтверждения: отдельный worktree и ветка от базовой ветки, commit, push и PR; merge пользователь выполняет на GitHub.

Ошибки анализа: 400/422 — входные данные; 504 — таймаут; 502 — ошибка локальной модели. Для сетевой папки: 404 — файл не найден или путь вне папки, 413 — файл больше лимита предобработки, 422 — не удалось прочитать ни один лог для общей сводки, 503 — папка недоступна. При отсутствии Ollama установите и запустите её, при отсутствии модели выполните `ollama pull qwen3:8b`.

## Необязательный GitHub

В `.env`: `GITHUB_TOKEN`, `GITHUB_REPOSITORY=owner/repository`, `GITHUB_DEFAULT_BRANCH=main`. Не публикуйте `.env`. Для fine-grained token разрешите доступ к нужному репозиторию и права Checks: Read (кнопка «Проверить CI»), Actions: Read (список упавших workflow и их логи), Contents: Read and write и Pull requests: Read and write (создание PR). После изменения `.env` перезапустите приложение. Сеть используется только при явных действиях GitHub. CI watcher:

```bat
.venv\Scripts\python.exe -m tools.watch_ci --repo C:\путь\к\репозиторию --once
```

Без `--once` работает опрос с интервалом `CI_POLL_INTERVAL_SECONDS`. Состояние обработанных запусков находится в `CI_STATE_DIR` (по умолчанию `../agent-ci-runtime`). Анализ использует текущие локальные исходники, не обязательно версию упавшего коммита; PR готовится от актуальной базовой ветки. Сверяйте этот контекст вручную.

## Проверки

```bat
.venv\Scripts\python.exe -m pytest -q
```

Для отдельной проверки настоящей скачанной модели выполните `.venv\Scripts\python.exe -m tools.verify_local_model`. Проверка вызывает локальную Qwen3 через API приложения, проверяет чтение исходников, предложение исправления, отказ без подтверждения и отсутствие дополнительных файлов; изменения делаются только во временном примере, GitHub не используется. Скорость выводится в терминале.

Перед показом исправления проверяется точное совпадение исходного фрагмента. При несовпадении модель получает одну попытку с фактическим содержимым файла; повторная ошибка отклоняет предложение без записи.

Тесты проверяют настройки, локальный адрес, цикл вызова инструментов, точную замену, защиту путей, API и подтверждение и отсутствие дополнительных файлов при применении. Они не скачивают модель и не измеряют качество Qwen3. Проверки адаптера через подставной HTTP-сервер проверяют протокол Ollama, но не заменяют реальный запуск модели.

## Архитектура и ограничения

`UploadFile → LogPayload → analyze_log/propose_fix → ChatOllama → локальная Ollama`.
При необходимости агент вызывает `search_directum_documentation`; поиск объединяет локальные FTS5/BM25 и векторы BGE-M3 по справке `rx262`.
Логи из сетевой папки идут по пути `resolve_share_log → preprocess_file → analyze_log` (маленькие `.json` — через `parse_log`), без копирования в репозиторий. Общая сводка использует `list_share_logs → scan_file(collect_context=False) → build_overview → analyze_log`; отдельный лог после сводки анализируется обычным `preprocess_file`.
Инструменты репозитория вызываются из Python в ограниченном цикле. Применение вынесено в `app/fixes.py` и не доступно модели. Гибридный RAG хранит индекс в локальном SQLite; автоматического merge нет. Сервис без авторизации предназначен для доверенного локального компьютера: не публикуйте порт в сеть.
