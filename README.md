# Directum Log Analyzer — локальная Qwen3 8B

FastAPI-сервис для анализа JSON-логов Directum и ошибок CI. Модель `qwen3:8b` работает через Ollama на этом компьютере, облачного резервного провайдера нет. Инструменты `read_git_file` и `search_code_in_repo` читают исходники внутри указанного корня репозитория. Предложение исправления само ничего не записывает: требуется подтверждение, проверяется точная замена и создаётся резервная копия.

## Установка на Windows

Нужен Python 3.11 или новее. Команды выполняются из папки `AI_checks_log`:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установите Ollama для Windows: https://ollama.com/download/windows . Запустите приложение и откройте новый терминал:

```bat
ollama pull qwen3:8b
ollama list
.venv\Scripts\python.exe -m tools.check_config
```

Для скачивания модели (около 5,2 ГБ) нужен интернет. После скачивания локальный анализ и интерфейс не требуют интернета. GitHub-интеграция отдельно требует сеть и токен. Если Ollama уже установлен, но не работает, запустите приложение Ollama; `ollama serve` нужен только если сервер ещё не запущен.

## Настройки

По умолчанию всё готово для локальной модели. При необходимости скопируйте `.env.example` в `.env` и измените:

```env
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
OLLAMA_TIMEOUT_SECONDS=180
OLLAMA_NUM_CTX=8192
```

Разрешён только локальный HTTP-адрес модели; системный HTTP-прокси не используется. Ключ GigaChat больше не нужен, старые `GIGACHAT_*` игнорируются. Не включайте внешнюю трассировку LangSmith для конфиденциальных логов. Большие логи и исходники могут не помещаться в контекст 8192 токена: выбирайте релевантные фрагменты. Увеличение `OLLAMA_NUM_CTX` увеличивает потребление памяти. Рассуждения модели отключены (`reasoning=False`) для уменьшения задержки. Это не гарантия качества: проверьте выводы по исходникам.

## Запуск

```bat
.venv\Scripts\python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/ . Выберите JSON-лог, при необходимости укажите корень репозитория, нажмите «Проверить лог». Затем «Предложить исправление», проверьте буквальный текст «Было / Станет» и только после проверки нажмите «Применить изменение». Форматирование результата — безопасный текст, без внешних скриптов и шрифтов. Модель не имеет инструмента записи файлов.

CLI:

```bat
.venv\Scripts\python.exe -m tools.analyze_json sample_log.json --repo .
```

При загруженной модели команда `ollama ps` показывает CPU/GPU-размещение. Измерьте скорость и качество на типичных обезличенных логах: причины, доказательства, реальные ссылки на прочитанный код, точный JSON исправления. Без установленной Ollama эти свойства нельзя подтвердить.

## API

- `GET /health` — только доступность FastAPI, не готовность модели. Для модели используйте `python -m tools.check_config`.
- `POST /analyze` — multipart `file` с непустым JSON-объектом, необязательный query `repo`.
- `POST /propose-fix?repo=...` — multipart `file`, предложение без записи файлов.
- `POST /apply-fix?repo=...` — JSON `path`, `explanation`, `old_text`, `new_text`, `approved`. Без `approved: true` — 403. Проверка пути и единственности исходного фрагмента, backup перед записью.
- `GET /repository/status?repo=...` — локальный Git, без токена.
- `GET /ci/checks?ref=...`, `POST /ci/scan?repo=...`, `POST /ci/propose-fix?run_id=...&repo=...` — необязательный GitHub CI.
- `POST /github/pull-request?repo=...` — только после подтверждения: отдельный worktree и ветка от базовой ветки, commit, push и PR; merge пользователь выполняет на GitHub.

Ошибки анализа: 400/422 — входные данные; 504 — таймаут; 502 — ошибка локальной модели. При отсутствии Ollama установите и запустите её, при отсутствии модели выполните `ollama pull qwen3:8b`.

## Необязательный GitHub

В `.env`: `GITHUB_TOKEN`, `GITHUB_REPOSITORY=owner/repository`, `GITHUB_DEFAULT_BRANCH=main`. Не публикуйте `.env`. Права токена: Actions Read, Contents Read and write, Pull requests Read and write. Сеть используется только при явных действиях GitHub. CI watcher:

```bat
.venv\Scripts\python.exe -m tools.watch_ci --repo C:\путь\к\репозиторию --once
```

Без `--once` работает опрос с интервалом `CI_POLL_INTERVAL_SECONDS`. Состояние обработанных запусков находится в `CI_STATE_DIR` (по умолчанию `../agent-ci-runtime`). Анализ использует текущие локальные исходники, не обязательно версию упавшего коммита; PR готовится от актуальной базовой ветки. Сверяйте этот контекст вручную.

## Проверки

```bat
.venv\Scripts\python.exe -m pytest -q
```

Для отдельной проверки настоящей скачанной модели выполните `.venv\Scripts\python.exe -m tools.verify_local_model`. Проверка вызывает локальную Qwen3 через API приложения, проверяет чтение исходников, предложение исправления, отказ без подтверждения и backup; изменения делаются только во временном примере, GitHub не используется. Скорость выводится в терминале.

Перед показом исправления проверяется точное совпадение исходного фрагмента. При несовпадении модель получает одну попытку с фактическим содержимым файла; повторная ошибка отклоняет предложение без записи.

Тесты проверяют настройки, локальный адрес, цикл вызова инструментов, точную замену, защиту путей, API и подтверждение с backup. Они не скачивают модель и не измеряют качество Qwen3. Проверки адаптера через подставной HTTP-сервер проверяют протокол Ollama, но не заменяют реальный запуск модели.

## Архитектура и ограничения

`UploadFile → LogPayload → analyze_log/propose_fix → ChatOllama → локальная Ollama`.
Инструменты репозитория вызываются из Python в ограниченном цикле. Применение вынесено в `app/fixes.py` и не доступно модели. RAG, базы векторов и автоматического merge нет. Сервис без авторизации предназначен для доверенного локального компьютера: не публикуйте порт в сеть.
